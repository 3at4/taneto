### 1. プロジェクトの基盤定義
#### 1.1. 概要
「タネト」は、AIを**「自己と対話するためのパートナー」**として機能するスマートフォンアプリです。妊活という、多くの男性にとって論理では割り切れない感情の旅路において、ユーザーが自分自身の心と身体の状態に耳を傾け、日々**「手入れ」**をすることで内なる穏やかさを育むことを支援します。AIはユーザーを評価・指導するのではなく、ただ寄り添い、問いかけ、内省を促すことで、ユーザー自身の力によるマインドセットの変革と、内発的な行動意欲の醸成を目指します。

#### 1.2. 背景と目的 (The "Why")
【解決したい課題】
従来の妊活サポートは、その多くが女性中心に設計されている。そのため、男性はしばしば「傍観者」となり、必要な情報やサポートから取り残されてきた。その結果、男性は以下のような深刻かつ特有のペインを一人で抱え込んでいる。

*   **情報的孤立:** 何をすべきか、何がリスクなのか分からず、漠然とした不安に苛まれる。
*   **心理的プレッシャー:** 「男らしさ」や「夫としての責任」というプレッシャーから、自身の問題を認められず、羞恥心や孤独感を深める。
*   **行動の麻痺:** 不安とプレッシャーから、妊活に対して受動的・回避的になり、結果としてパートナーとの間に深刻な「温度差」やコミュニケーション不全を生んでしまう。

【目的】
本プロダクトの目的は、この**「男性特有のペイン」**を解消することにあります。AI対話パートナーが個別に寄り添い、ユーザーが自分自身の心と身体の状態に耳を傾け、日々「手入れ」をすることで内なる穏やかさを育むことを支援します。これにより、男性が自信と主体性を取り戻し、真の意味でパートナーと手を取り合って妊活に臨める社会の実現を目指します。

#### 1.3. ゴール
【ユーザーへの提供価値】
*   **穏やかな自己受容:** スコアや評価から解放され、自身のポジティブな状態もネガティブな状態も、ありのままに認識し、受け入れることができるようになる。
*   **内発的モチベーションの醸成:** 「やらなければならない」という義務感からではなく、「自分の庭を育みたい」という自然でポジティブな愛着から、心身をケアする行動を継続できるようになる。
*   **本質的な自信の再構築:** 他者との比較や目標達成ではなく、日々の「手入れ」と「自己との対話」を通じて、揺るぎない自己肯定感を育む。

【ビジネス目標】
*   **市場でのリーダーシップ確立:** 男性向け妊活支援アプリという未開拓市場において、3年以内にNo.1のMAU（月間アクティブユーザー数）を獲得する。
*   **エンゲージメント:** アプリ利用開始後、1ヶ月の継続率（リテンションレート）を40%以上達成する。
*   **マネタイズ:** Phase 2以降、プレミアム機能（例: 専門家によるオンライン相談、高度なAI分析レポート）を導入し、有料課金率5%を目指す。

### 2. ターゲットユーザーと課題の深掘り
#### 2.1. ターゲットユーザー（ペルソナ）
*   **ペルソナ名:** 健太（Kenta）
*   **年齢:** 34歳
*   **背景:**
    *   都心在住、上場企業勤務（年収600万円）。結婚3年目で、同い年の妻と二人暮らし（共働き）。
    *   これまで勉強、就職、仕事、そして結婚と、人生の主要なイベントを計画通り、努力によって達成してきた。ロジカルな思考を好み、物事をデータや事実ベースで判断する傾向がある。
*   **価値観・性格:**
    *   自己管理能力が高く、物事が自身のコントロール下にある状態を好む。
    *   問題解決においては、具体的な目標と達成までの道筋が明確であることを重視する。
    *   プライドが高く、他人に「弱み」を見せることに強い抵抗がある。特に、自身の能力不足を認めることは、彼のアイデンティティを揺るがす一大事である。
*   **現状と妊活へのスタンス:**
    *   当初は「結婚すれば子どもは自然にできるだろう」と楽観視していた。しかし、1年以上経っても授からない現実に直面し、人生で初めて「計画通りに進まない」という壁にぶつかっている。
    *   妻が自分より先に情報を集め、焦りや不安を見せるたびに、プレッシャーを感じている。しかし、何をどうすれば良いか分からず、具体的な行動に移せないでいる。この無力感が、彼をさらに苛立たせている。
    *   不妊の原因が自分にある可能性など、考えたこともなかった。そのため、この問題は「妻が解決すべきこと」という無意識のバイアスを持っている可能性がある。
*   **代表的な心の声:**
    *   「仕事もプライベートも、計画通りに進めてきた。でも、こればっかりは、何をどうすればいいのか全く分からない。妻は焦っているように見えるし、プレッシャーだけが増えていく…。何が問題で、俺に何ができるんだ？」

#### 2.2. ユーザーが抱える課題（ペインポイント）
健太が直面しているペインは、単一ではなく複合的である。

*   **【情報的ペイン】知識のブラックボックス**
    *   **何が問題か分からない:** 不妊原因の約半分が男性側にもあるという事実を知らない 。問題の所在が不明なため、行動の第一歩が踏み出せない。
    *   **何をすべきか分からない:** 自身の生活習慣（長風呂、ストレス、食事など）が精子の質に影響を与えることを具体的に認識していない。
    *   **検査結果の意味が分からない:** いざ検査を受けても、専門用語や数値（精子濃度、運動率など）が何を意味し、自分の状況がどれほど深刻なのかを直感的に理解できない。
*   **【心理的ペイン】アイデンティティの危機**
    *   **コントロール感の喪失:** 人生を計画的にコントロールしてきた彼にとって、妊活は唯一コントロール不能な領域。この無力感が、彼の自信を根底から揺るがす。
    *   **プライドの毀損と羞恥心:** 「男性不妊」の可能性は、「男としての欠陥」という烙印のように感じられ、認めたくない。この羞恥心が、検査や治療への積極的な関与を妨げる最大の心理的障壁となる。
    *   **深刻な孤独感:** この悩みは極めてデリケートであり、プライドが邪魔をして友人や同僚には絶対に相談できない。結果、誰にも本音を打ち明けられず、一人で苦悩を抱え込むことになる。
*   **【行動的ペイン】課題からの回避とすれ違い**
    *   **課題からの回避:** 上記の心理的ペインが原因で、妊活の話題そのものを避けたり、非協力的に見えたりする行動を取ってしまう。
    *   **パートナーとの温度差:** 彼の回避的な態度は、パートナーからは「無関心」「やる気がない」と映り、深刻なすれ違いや衝突の原因となる。

#### 2.3. プロダクトによる解決策と提供価値（ベネフィット）
「タネト」は、AI対話パートナーを通じて、これらのペインを解決し、以下の価値を提供します。

| ユーザーのペイン | タネトによる解決策 (ソリューション) | ユーザーが得られる便益 (価値) |
| :--- | :--- | :--- |
| 情報的孤立と行動の麻痺 | AIが日々投げかける**「問いかけ」**に答える形で、自身の状態や思考を整理する（ジャーナリング）。AIは、その時々のユーザーの状態に最適な「手入れの方法（知識）」をそっと提示する。 | 「何をすべきか」を外に求めるのではなく、「自分はどうしたいか」を内側から見出す力が養われる。行動の麻痺が解け、納得感のある一歩を踏み出せる。 |
| 心理的プレッシャーと傷つくプライド | スコアや評価を廃し、自身の状態を**「庭」**として比喩的に表現。日々の行動は、庭を「手入れ」する行為として記録される。 | 「評価される」というプレッシャーから解放され、心穏やかに自分と向き合える。庭を育てる喜びが、自己肯定感を高める。 |
| パートナーとの断絶と孤独感 | まずは自分自身の感情を穏やかにすることで、パートナーに対して心に余裕を持って接することができるようになる。 | 自分の感情が受け止められたという感覚を通じて孤独感が和らぎ、パートナーと向き合うための精神的な土台が築かれる。 |

### 3. 製品スコープと主要機能の定義
#### 3.1. 主要機能（モジュール）
本プロダクトは、ユーザーが「自己との対話」と「手入れ」を通じて内なる穏やかさを育むため、以下の3つのコア機能モジュールで構成される。
1.  **エモーショナル・オンボーディング:** ユーザーのマインドセットをリセットし、アプリの世界観へと深く引き込む導入機能。
2.  **ジャーナリング・パートナー:** AIとの対話（問いかけ）を通じて、ユーザーの内省を促し、思考と感情を整理する機能。
3.  **マインドフル・ガーデン:** ユーザーの心身の状態を比喩的に可視化し、日々の「手入れ」への内発的モチベーションを育む機能。

#### 3.2. スコープ（今回のリリース範囲）
MVPでは、**ユーザーが一人で、日々の「問いかけ」に応え、「庭」を手入れする、というコア・ループを確立すること**を最優先目標とする。このサイクルを通じて、ユーザーが穏やかな自己受容と内発的な行動意欲の萌芽を感じられる体験を創出する。

| 機能モジュール | MVPで実装する具体的な機能 | ユーザー課題への貢献 |
| :--- | :--- | :--- |
| 1. エモーショナル・オンボーディング | 没入型プロローグ: パートナーの視点を描く、スキップ不可のショートストーリー（マンガ/簡易アニメーション）を初回起動時に再生する。 | 【共感の醸成】 ユーザーの防御的な姿勢を解き、妊活を「二人ごと」として捉えるマインドセットの土台を築く。 |
| 2. ジャーナリング・パートナー | AIからの「今日の問いかけ」: ユーザーの状態や過去の記録（MVPでは日付や曜日など簡易的なロジック）に基づき、AIが毎日1つ、内省を促す問いをホーム画面に提示する。 | 【内省の習慣化】 「何をすべきか」ではなく「自分はどう感じるか」を考える習慣を促し、情報的孤立と行動の麻痺を内側から解消する。 |
| | プライベート・ジャーナル機能: 「問いかけ」に対して、ユーザーが自由にテキストを書き、保存できる機能。記録は完全にプライベートで、誰にも共有されない。 | 【心理的安全性の確保】 誰にも言えない本音や不安を吐き出せる安全な場所を提供し、心理的プレッシャーを軽減する。 |
| | 受容的なAIフィードバック: ジャーナルを保存すると、AIが定型的な受容の言葉（例：「言葉にしてくださり、ありがとうございます。その感情はあなただけの大切なものです」）を返す。※MVPでは、内容の解析は行わない。 | 【孤独感の緩和】 自分の感情が「受け止められた」という感覚を提供し、孤独感を和らげる。 |
| 3. マインドフル・ガーデン | 心象風景としての「庭」: ホーム画面の背景に、ユーザーの状態を反映したシンプルな庭のビジュアルを表示する。 | 【状態の可視化】 スコアという評価ではなく、比喩的な風景として状態を認識させることで、穏やかな自己受容を促す。 |
| | 「手入れ」による庭の変化: ユーザーの行動ログ（下記参照）に応じて、庭の状態がポジティブ/ネガティブに変化する。※MVPの変化はシンプルに（例：花が咲く/しぼむ、天気が晴れる/曇る）。 | 【内発的モチベーション】 「庭を良い状態に保ちたい」という自然な愛着が、日々のセルフケア行動へのモチベーションとなる。 |
| | 基本的な「手入れ」（ログ記録）機能: 庭の状態に影響を与える、以下の基本的な行動を簡単に入力できる機能。（例：睡眠時間、運動の有無、ジャーナリングの実施） | 【行動の意識化】 自分の日々の行動が、自分の心身（庭）にどう影響するかを意識させる。 |

#### 3.3. スコープ外（やらないこと）
以下の機能は、MVPのスコープ外とする。
*   **直接的なコミュニケーション機能:** 変更なし。スコープ外。
*   **高度なAI機能:**
    *   **ジャーナルの自然言語解析と、それに基づくパーソナライズされたフィードバック。**
    *   ユーザーの感情分析。
    *   **理由:** MVPでは、まず「問いかけ→記録→受容」というコア・ループの価値を検証する。AIの高度化はPhase 2以降の課題とする。
*   **高度なガーデン機能:**
    *   多様な植物やアイテムによる庭のカスタマイズ機能。
    *   季節や天候のリアルタイムな変化。
    *   **理由:** MVPでは、状態を反映するメタファーとして機能すれば十分。装飾的な要素は後回しとする。
*   **マネタイズ機能、多言語対応:** 変更なし。スコープ外。

### 4. 要件の具体化（機能・非機能）
#### 4.1. 機能要件
##### 4.1.1. エモーショナル・オンボーディング (Must-have)
*   **ユースケース:**
    1.  ユーザーが初めてアプリを起動する。
    2.  システムは、スキップ不可のプロローグ（マンガまたは簡易アニメーション形式）を表示する。
    3.  プロローグは、パートナー（女性）視点で、妊活の話題を切り出すまでの孤独、不安、葛藤を描写する。
    4.  ストーリーの最後に、ユーザーの内省を促す問いかけを表示し、次の「初期設定（庭の準備）」へ自動的に遷移する。
*   **要件:**
    *   コンテンツは感情に訴えかけるストーリーテリングを重視する。
    *   UIは没入感を高めるため、極力シンプルにする。
    *   再生時間は15~30秒程度とする。

##### 4.1.2. ジャーナリング・パートナー (Must-have)
*   **ユースケース: ジャーナルの記録**
    1.  ユーザーはホーム画面で、AIから提示された「今日の問いかけ」を確認する。
    2.  問いかけ部分をタップすると、ジャーナル入力画面に遷移する。
    3.  ユーザーは、問いかけに対する思考や感情を自由にテキストで入力する。
    4.  ユーザーが「記録する」ボタンをタップすると、入力内容が保存される。
    5.  システムは、「言葉にしてくださり、ありがとうございます」といった受容的なフィードバック（定型文）をモーダルで表示し、ホーム画面に戻る。
*   **ユースケース: 過去のジャーナルの閲覧**
    1.  ユーザーはホーム画面の特定アイコン（例：日記帳のアイコン）をタップする。
    2.  システムは、過去のジャーナル記録を日付順のリストまたはカレンダー形式で表示する。
    3.  ユーザーは、特定の日付をタップして、その日の「問いかけ」と自身の「記録」を読み返すことができる。
*   **要件:**
    *   **問いかけ生成ロジック (MVP):** 約30種類の問いかけを事前に用意し、ランダムまたは日付（例：1日は〇〇、2日は△△）に基づいて日替わりで提示する。
    *   **入力インターフェース:** 集中して書き込めるよう、装飾のないシンプルなテキストエディタ画面とする。文字数制限は設けない。
    *   **プライバシー:** 入力されたジャーナルデータは、ユーザーのデバイス内に暗号化して保存され、外部サーバーには送信されないことをプライバシーポリシーに明記する。
    *   **AIフィードバック (MVP):** 5パターン程度の受容的な定型文を事前に用意し、保存時にランダムで1つ表示する。**内容は解析しない。**

##### 4.1.3. マインドフル・ガーデン (Must-have)
*   **ユースケース: 庭の観察と変化**
    1.  ユーザーはホーム画面で、自身の心身の状態を反映した「庭」の風景を常に確認できる。
    2.  ユーザーが日々の「手入れ」（ログ記録）を行うと、庭のビジュアルが翌日のアプリ起動時に変化している。（例：昨日よく眠れたら、庭の天気が「曇り」から「晴れ」になっている）
    3.  ジャーナルを記録すると、庭に小さな花が一つ咲くなど、ポジティブな変化が起こる。
*   **ユースケース: 庭の「手入れ」（ログ記録）**
    1.  ユーザーは、ホーム画面の「手入れをする」ボタンをタップする。
    2.  システムは、記録項目（昨晩の睡眠時間、今日の運動の有無、今のストレスレベル）をシンプルなUIで表示する。
    3.  ユーザーは数タップで各項目を選択・入力し、「記録する」ボタンを押す。
*   **要件:**
    *   **庭のビジュアル (MVP):**
        *   背景はシンプルな芝生と一本の木を基本とする。
        *   状態を表す要素は、「天気（晴/曇/雨）」「木や花の状態（元気/しおれている）」「蝶の有無」の3つに絞る。
    *   **変化のロジック (MVP):**
        *   「手入れ」の記録値に基づき、庭の各要素の状態を決定するシンプルなルールベースを定義する。
        *   例1：睡眠時間 > 7時間 → 天気 = 晴れ
        *   例2：運動 = 実施 → 蝶が出現
        *   例3：ストレスレベル = 高い → 木や花の状態 = しおれている
        *   例4：ジャーナル = 実施 → 新しい花が咲く
    *   **ログ記録のUI:**
        *   睡眠時間：選択式（例：〜5時間, 5-6時間, 6-7時間, 7時間以上）
        *   運動の有無：トグルスイッチ (ON/OFF)
        *   ストレスレベル：3段階の顔アイコンから選択

#### 4.2. 非機能要件
*   **パフォーマンス:** アプリ起動3秒以内、画面遷移1秒以内。
*   **セキュリティ:** 全てのユーザーデータはデバイス内で安全に管理。
*   **UI/UX:**
    *   ダークモードを基調とし、男性が落ち着いて内省できるデザイン。
    *   「庭」のイラストは、リアルすぎず、抽象的すぎず、愛着が湧くような、穏やかで洗練されたタッチを目指す。
    *   操作は直感的で、チュートリアルなしでも利用できるシンプルさを追求する。

### 5. 優先順位付け
#### 5.1. 優先順位付けの基準
*   **ユーザーインパクト:** ターゲットユーザー「健太」の最も深刻なペイン（心理的プレッシャー、孤独感）を和らげ、**「自己との対話」**という新しい体験を提供できるか。
*   **プロダクトの核心価値:** 「解決」ではなく「手入れ」という本プロダクト独自の思想を、ユーザーが初日から体感できるか。
*   **機能間の依存関係:** 他の機能が成立するための前提条件となるか。

#### 5.2. 優先度評価
MVPで定義した3つの主要機能モジュールは、ユーザーに一貫した世界観と体験を提供するために不可分であり、すべてを**「Must-have」**と位置づける。

| 機能モジュール | 優先度 | 理由 |
| :--- | :--- | :--- |
| 1. エモーショナル・オンボーディング | Must-have | 【世界観への招待状】 これがなければ、ユーザーはこのアプリが単なるログツールではないことを理解できない。ユーザーを「評価される世界」から「対話する世界」へと導く、最も重要な意識の転換装置。 |
| 2. ジャーナリング・パートナー | Must-have | 【自己との対話のコア】 ユーザーが内省し、感情を吐き出すための具体的な「場」。この機能がなければ、「手入れ」の動機付けが生まれず、「庭」はただの背景になってしまう。プロダクトの思想を体現する中核エンジン。 |
| 3. マインドフル・ガーデン | Must-have | 【感情の鏡と育てる喜び】 ジャーナリングという内的な行為を、目に見える情緒的な変化へと繋げるためのフィードバック装置。この「庭」がなければ、ユーザーは自分の行動のポジティブな影響を実感できず、継続のモチベーションを失う。 |

#### 5.3. 優先度の要約
本アプリのMVPは、**「ユーザーの心を動かし(1) → 内省する場を提供し(2) → その結果を情緒的にフィードバックする(3)」**という一連の体験フローそのものが価値です。このサイクルを通じて初めて、ユーザーは「解決」のプレッシャーから解放され、「手入れ」という新しい自己との向き合い方を学ぶことができます。

したがって、これら3つの機能モジュールは、どれか一つでも欠けるとプロダクトの核心的価値が著しく損なわれるため、すべてを**「Must-have」**として定義し、MVP開発における最優先事項とします。
